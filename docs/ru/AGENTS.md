# Обязательные инструкции для ИИ-агентов разработки

[English](../../AGENTS.md)

1. До написания кода прочитайте `README.md` и все упомянутые спецификации V1.
2. Не реализуйте V2 или V3 до прохождения приёмки V1; избегайте умозрительных абстракций.
3. Делайте короткие, удобные для проверки коммиты по отдельным функциям; соблюдайте `governance/git.md` и `governance/quality.md`.
4. Не меняйте и не удаляйте описанную модель безопасности ради упрощения разработки.
5. Не заявляйте без оговорок, что локальный HTTP защищён от злоумышленника в LAN. Незашифрованный трафик — известное ограничение; документируйте компромиссы развёртывания и требуйте подтверждения сопряжения на ТВ.
6. Не открывайте произвольные localhost/LAN-ресурсы через endpoint приёмника; сервер не должен загружать произвольные URL или быть открытым прокси.
7. При изменении форм API поддерживайте `protocol/openapi.yaml` и соответствующие тесты.
8. Каждое новое поведение должно иметь модульные или интеграционные тесты, включая некорректный ввод и неавторизованный доступ.
9. Для ТВ предпочтительны нативные Kotlin Android SDK API, для CLI — Go, для веба — TypeScript. Не добавляйте Go runtime в Android TV.
10. Не обещайте полную совместимость сайтов: страницы могут зависеть от Widevine, cookies, браузеров, ввода с пульта и других факторов.
11. `.pen` — редактируемые эталоны. Проверяйте их в Pencil до заявления о точном визуальном соответствии.
12. Обновляйте документацию в том же PR, что и поведение. Не допускайте секретов и токенов в Git и логах.
13. Сохраняйте архитектуру с приоритетом приватности: без удалённой телеметрии и обязательных внешних сервисов.
14. При блокировке укажите точную причину и минимальный проверяемый обходной путь; не имитируйте реализацию, тесты или скриншоты.
