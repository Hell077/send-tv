# Контракт API

[English](../../../architecture/api.md)

V1: HTTP JSON, базовый путь `/v1`. `protocol/openapi.yaml` — канонический источник форм запросов и ответов.

## Ресурсы
- `GET /v1/info`: идентификатор, версия протокола, возможности; без секретов.
- Challenge создаётся только на ТВ; HTTP-endpoint для него нет. QR несёт временный challenge во фрагменте URL.
- `POST /v1/pair`: challenge и предлагаемое имя; нужно разрешение ТВ; возвращается ожидание, а доступ выдаётся только после разрешения.
- `GET /v1/pair/{requestId}`: опрос с отдельными ограниченными по сроку 256-битными bearer-данными. Сам request ID никогда не разрешает выдачу токена.
- `DELETE /v1/pair/{requestId}`: отмена ожидающего запроса с его polling-данными.
- `POST /v1/open`: `Authorization: Bearer <token>` и `{url, requestId}`; при постановке в очередь — `{operationId,status:accepted}`.
- `GET /v1/operations/{id}`: accepted/launching/launched/failed; нельзя подразумевать загрузку страницы.
- Отзыв и перечисление устройств — локальные методы ТВ, не HTTP-endpoint.

## Форма ошибки
`{code: "INVALID_URL", message: "Only http(s) links are supported", requestId: "..."}`. Не включайте секреты в сообщения. Поля и коды протокола не переводятся; переводится интерфейс клиента.

## Семантика
- `launched` означает принятие ACTION_VIEW системой Android, а не полную отрисовку страницы.
- Приёмник ограничивает размер URL, отклоняет обход схем, встроенные данные входа и слишком большой JSON.
- Опрос сопряжения не должен выдавать токен тому, кто знает только угадываемый ID.
- `open` защищён от быстрых повторов: `requestId` — ключ идемпотентности с ограниченным TTL.

## Версии
В v1 только аддитивные изменения; несовместимое изменение → `/v2`. Клиент проверяет возможности, а не выводит их только из названия платформы.
