# Проверка CI V1

[English](../../ci-v1.md)

Первый запуск hosted CI упал: действие настройки Android запросило устаревший пакет SDK `tools`. Теперь workflow явно запрашивает `platform-tools`.

Следующий запуск отклонил npm lockfile с ключами пакетов из временного каталога. Lockfile, созданный через симлинк временного prefix, оказался непереносимым на Linux runner. Пути исправлены на `node_modules/` относительно репозитория. Чистая установка `npm ci --ignore-scripts --no-audit --no-fund` с точными зафиксированными manifest/lock проверена в отдельном каноническом временном каталоге.

`node scripts/check-lockfile.mjs` заранее отклоняет пути вне `node_modules/`, отсутствующие объявленные пакеты и несовпадение корневых зависимостей с `package.json`. Регрессионные тесты `node --test scripts/check-lockfile.test.mjs` запускаются до установки зависимостей в обоих CI jobs. Они дополняют npm, но не подтверждают безопасность зависимостей.

Для каждой отправленной ревизии нужно смотреть hosted CI. Локальный успех не выдаётся за успешный hosted run.
