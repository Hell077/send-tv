# Автомат безопасности сопряжения V1

[English](../../pairing-v1.md)

Kotlin-ядро использует случайный 256-битный challenge от ТВ, действующий 60 секунд и расходуемый при отправке запроса. Разрешение — локальный метод интерфейса владельца; HTTP-endpoint для него нет. Отказ, отмена, таймаут и перезапуск сеанса не могут разрешить запрос. Для опроса выдаются отдельные 256-битные данные: request ID сам по себе не даёт доступ.

Разрешённые bearer-токены — случайные 256-битные значения. В постоянное хранилище передаются только SHA-256-хеши. Открытый токен остаётся в памяти в ограниченном ответе опроса до исходного 60-секундного срока, позволяя повторить получение; перезапуск сеанса стирает это состояние. Отзыв немедленно отключает авторизацию и стирает ожидающую выдачу токена этого устройства. Ошибка сохранения не даёт новый доступ.

Не более 8 запросов и 32 доверенных устройств. Не более 5 отправок на источник в минуту и 20 в целом; число bucket источников ограничено. Повторные и истёкшие challenge отклоняются. Лимиты уменьшают злоупотребления, но не делают враждебную LAN безопасной. HTTP раскрывает challenge, polling-данные, токены и целевые URL наблюдателям; сопряжение всегда требует подтверждения на ТВ.

Валидатор принимает только синтаксически корректные HTTP(S) URI с хостом, без данных входа, пробелов/управляющих символов, с корректным портом и пределом 4096 символов. Проверка никогда не загружает адрес. Android dispatch и интеграция транспорта — отдельные последующие инкременты исходного плана.
