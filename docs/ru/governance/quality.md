# Проверки качества

[English](../../../governance/quality.md)

- Kotlin: ktlint или detekt; JVM-тесты валидатора URL, автомата сопряжения и авторизации; instrumentation-тест Intent там, где доступен.
- Go: `gofmt`, `go vet`, `go test -race ./...` на поддерживаемых CI runner; контрактные тесты discovery/parser.
- TypeScript: строгий TS, ESLint, Prettier, Vitest, Playwright для критичных сценариев отправителя и сайта.
- Каждое исправление имеет регрессионный тест; нестабильные тесты отслеживаются, а не молча игнорируются.
- Минимальная цель — целевые тесты всех ветвей безопасности и протокола, а не произвольное обещание 100% общего покрытия.
- В фикстурах нет реальных секретов. Проверяйте отсутствие URL-секретов и токенов в логах.
- Доступность: клавиатура, видимый фокус, контраст, подписи для скринридера, D-pad на ТВ.
- Где возможно, воспроизводимая сборка; фиксируйте версии зависимостей, проверяйте их в CI.
- Для merge нужны успешный CI, актуальная документация и проверенная приёмка текущей версии.
