# Спецификация сайта и документации

[English](../../../website/website-spec.md)

## Хостинг и архитектура
GitHub Pages через Actions, только статическая сборка. Рекомендуемый стек Astro + TypeScript + MDX или другой обоснованный генератор. Лендинг `/`, версионированные руководства `/docs/`; русские страницы `/ru/`. Нет зависимости от работающего ТВ, серверного API, обязательных аккаунтов и отслеживания.

## Структура
- `/`: продукт, три шага, дизайн-демо, матрица, приватность, GitHub, документация; загрузка только при реальном релизе.
- `/docs/getting-started`: установка, поддерживаемые ТВ, браузер, сопряжение, отправка.
- `/docs/cli`: только после V2; до неё правдивое описание планов и версии.
- `/docs/troubleshooting`: LAN, QR, отсутствие браузера, гостевая изоляция, авторизация.
- `/docs/architecture`: сценарий, протокол, ограничения приватности и безопасности.
- `/docs/api`: OpenAPI и примеры без секретов.
- `/docs/faq`: Samsung/LG, Интернет, установка, трансляция экрана.
- `/privacy`, `/changelog`; `/download` только с реальным релизом.

## Дизайн и текст
Соблюдайте `design/website/design.md` и `website.pen`: минималистичный тёмно-синий с голубым акцентом, контраст, сдержанные градиенты, технический и дружелюбный тон. Без выдуманных оценок/логотипов. Макеты устройств явно названы иллюстрациями. CTA: начать, читать документацию, GitHub. Не обещайте всеобщую ТВ-совместимость.

## Документация
Левая навигация desktop, сворачиваемое мобильное оглавление, локальный поиск где возможно, копирование кода, понятные метки платформ, скриншоты с alt, глубокие ссылки, дата/версия, предупреждение HTTP LAN. Языковой переключатель сохраняет соответствие материала.

## SEO и производительность
Семантические заголовки, OpenGraph, sitemap.xml, canonical из реальных настроек, robots.txt, lazy media, alt, адаптивность 360–1920 px. Цель Lighthouse ≥90 по производительности/доступности на поддерживаемом CI-измерении, не гарантия до проверки.

## Публикация
Actions: locked deps → typecheck → тесты → build → Pages artifact → deploy только main. `base` учитывает project Pages `<repo>` и корневой custom domain; owner/URL не выдумываются. Отдельная стратегия PR preview при необходимости; SPA redirects не должны поглощать документацию. Настройку Pages документируйте.
