[Канонический OpenAPI](../../../protocol/openapi.yaml) определяет формы запросов и ответов. V1 проходит проверку. Базовый путь: `/v1`; порт по умолчанию: `8765`, меняется на ТВ.

| Метод / путь                  | Авторизация                         | Назначение                                     |
| ----------------------------- | ----------------------------------- | ---------------------------------------------- |
| `GET /v1/info`                | Открытый                            | Идентификатор и возможности, без секретов      |
| `POST /v1/pair`               | Свежий QR challenge и точный Origin | Запрос разрешения на ТВ                        |
| `GET /v1/pair/{requestId}`    | Отдельный polling bearer            | Ожидание, отказ или выдача разрешённого токена |
| `DELETE /v1/pair/{requestId}` | Polling bearer и точный Origin      | Отмена ожидающего запроса                      |
| `POST /v1/open`               | Доверенный bearer и точный Origin   | Постановка передачи ссылки в очередь           |
| `GET /v1/operations/{id}`     | То же доверенное устройство         | Закрытый статус передачи                       |

Создание challenge, разрешение, список доверенных устройств и отзыв доступны только локально на ТВ. Нет HTTP-прокси или произвольного пути к ресурсам.

Пример тела с ключом идемпотентности в пределах доверенного устройства:

```json
{ "url": "https://example.com/", "requestId": "redacted-example-0001" }
```

Заголовки: `Content-Type: application/json`, `Authorization: Bearer <redacted>` и точный `Origin` приёмника, например `http://192.168.1.42:8765`. Host должен совпадать с адресом и портом. Отправитель задаёт их автоматически; произвольный сайт не может подставить собственный Origin.

```json
{ "operationId": "opaque-operation-id", "status": "accepted" }
```

Опросите возвращённую операцию. Статусы: `accepted`, `launching`, `launched`, `failed`. `launched` означает, что Android принял передачу, а не что страница загрузилась. Другой URL с тем же ключом идемпотентности отклоняется с 409.

Ошибка содержит `code` и `message`, без целевого URL и данных доступа. Примеры: `INVALID_URL`, `UNAUTHORIZED`, `INVALID_ORIGIN`, `INVALID_CHALLENGE`, `RATE_LIMITED`, `NO_BROWSER`, `RETURN_TO_RECEIVER`. Протокольные поля и коды ошибок одинаковы в обоих языках; переводится интерфейс.

Сервер принимает ограниченное подмножество HTTP/1.1: запрос на соединение, Content-Length для POST, без chunking и повторяющихся заголовков, до 8 KiB заголовков и 16 KiB тела. Все ответы — no-store. Ограничения незашифрованной LAN описаны в [архитектуре](../architecture/).
